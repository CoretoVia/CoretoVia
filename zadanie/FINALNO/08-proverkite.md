# ПРОВЕРКИТЕ · как програмата пази себе си

Този раздел казва на ИИ, който строи наново, **как да знае, че е построил вярно**.
Останалите раздели описват какво трябва да прави програмата; този описва **машините,
които не ѝ позволяват да спре да го прави**.

Правилото над всичко тук е едно: **числата се БРОЯТ от изхода на командата, не се
преписват** (правило 14). Всяко число долу е взето от команда, не от документ.

---

## 1 · ДЕВЕТТЕ ПОРТИ · какво минава преди всеки коммит

Една команда ги вика всичките, в този ред, и спира на първата червена:

```
npm run proverka
  = typecheck && test && chistota && chestnost && sloeve && knip
    && litsenzi && dumi:proveri && stil
```

| # | порта | какво прави | какво брои днес |
| :--: | :---- | :---- | :---- |
| 1 | **typecheck** | `tsc --noEmit` · нула грешки на типовете | — |
| 2 | **test** | `vitest run` | **58 файла · 532 теста** |
| 3 | **chistota** | обходи за мъртво, излишно и шум | **12 обхода**, седем на праг нула |
| 4 | **chestnost** | обходи за дефекти в САМИТЕ проверки | **11 обхода** (А…К), всичките на нула |
| 5 | **sloeve** | посоката на зависимостите | **117 модула · 548 зависимости · нула нарушения** |
| 6 | **knip** | недостижим код и неизползвани изнасяния | нула |
| 7 | **litsenzi** | лицензите на всичко в пакета | **202 пакета · 0 извън списъка** |
| 8 | **dumi:proveri** | неговите думи от Книгата срещу кода | **42 думи = 42 · разлика 0** |
| 9 | **stil** | `biome check --error-on-warnings` | **210 файла** |

И отделно, не в `proverka`, защото иска браузър:

```
npm run proba      # строи и минава през ИСТИНСКИ браузър · ДВА пъти поред
```

**Изискване:** ход не е затворен, докато деветте не са зелени И проходът не е минал
**два пъти** с „НАХОДКИ: няма".

## 2 · ЧИСТОТАТА · дванайсет обхода

**Какво пази:** че в кода няма нищо, което не върши работа. Мъртвото и излишното не са
безобидни — те лъжат за програмата.

**Седем обхода са на праг НУЛА** (една находка е червено):

| # | обход | какво лови |
| :--: | :---- | :---- |
| 1 | **мъртво** | име, което никой не вика |
| 2 | **излишен export** | изнесено, а се ползва само вътре в своя файл |
| 4 | **празно поле** | обявено поле, което никога не получава стойност |
| 5 | **излишен ред** | ред, който не мени нищо |
| 6 | **несвързан** | файл, до който не води път |
| 9 | **път до HTML извън вратата** | HTML се пише само през запечатания път |
| 10 | **шум · диагностика извън записа** | `console.*` вместо записа |

**Два обхода са с праг НАД нулата** — заварено, което не бива да РАСТЕ:

| # | обход | праг |
| :--: | :---- | :--: |
| 8 | дублирано (по букви) | 1 |
| 8б | дублирано **по СТРУКТУРА** · същата форма, различни имена | 2 |

**Три са БРОЯЧИ без праг** — казват, не спират:

| # | брояч | какво казва |
| :--: | :---- | :---- |
| 3 | **само тест** | изнесено, което вика САМО тестът · днес **33** |
| 3б | изнесено за теста | същото, по друг разрез |
| 7 | **без тест** | файл, който никой тест не внася |

**Изискване:** всеки обход **КАЗВА КОЛКО Е ВИДЯЛ** („видени 573 имена" · „видени 112
файла"). Обход, който отчита нула, без да е погледнал, е по-опасен от липсващ обход —
затова броенето на видяното е част от договора, не украса.

## 3 · ЧЕСТНОСТТА · единайсет обхода срещу САМИТЕ проверки

**Какво пази:** че тестовете не лъжат. Тук се лови **зелен тест, който не може да падне**.

| буква | какво лови |
| :--: | :---- |
| **А** | **тестът се мести заедно с кода** · очакваното се строи от същата константа, която проверява → тестът никога не пада |
| **Б** | гол селектор върху двусмислен белег · белег, който живее на два екрана |
| **В** | **константа без нито един пин с ръка** · числото се проверява срещу себе си |
| **Г** | цикъл с очакване върху списък, който може да е празен · `[].every(...)` е `true` |
| **Д** | подпроцес в тест без обявено време · виси мълчаливо |
| **Е** | четене без изчакване след действие · мигащ тест |
| **Ж** | пише след прерисуване и подава, без проверка |
| **З** | праг за скорост върху ЕДНО измерване · шумът минава за истина |
| **И** | **проверка, която ПИШЕ в дървото на проекта** |
| **Й** | **обход по файлове без твърдение колко е видял** |
| **К** | в прохода: праг вместо число |

**Всичките единайсет са на праг НУЛА.**

**Изискване:** обходът трябва да може да намери дефект **в себе си**. Три от единайсетте
са родени точно така — намерени са в собствения си код.

## 4 · СЛОЕВЕТЕ · посоката е една

**Какво пази:** К2 — Портата е една, и зависимостите сочат в ЕДНА посока.

```
ядро (src/yadro)  →  домейн  →  огледало  →  екран
                              ↑
                     екранът НЕ знае нищо за носителя
```

Брои се от `depcruise`. **Изискване:** нула нарушения, и числата (модули · зависимости)
се четат от изхода, не се преписват.

---

## 5 · ПРОХОДЪТ · истински браузър, два пъти

**Какво пази:** че построеното наистина работи, а не само че типовете се връзват.

**Изискване:** минава **два пъти поред** с нула находки. Веднъж не стига — мигащ тест
минава веднъж.

## 6 · ТЕСТОВЕТЕ, КОИТО ПАЗЯТ КОНСТИТУЦИЯТА

Освен обходите, отделни тестове пазят правила, които иначе биха се спазвали „по
дисциплина":

| какво пази | правило |
| :---- | :---- |
| **осемте прозореца** · девети няма команда и няма път | К1 |
| **латиница и кирилица не се смесват в една дума** | 10 |
| **поверителността** · нула лични данни в публичното хранилище · един позволен имейл · нула `.xlsx` извън мострите · нула телефони | 21 |
| **библиотеките** · пин с ръка · `package.json` трябва да съвпадне с него, не обратното | 9 |
| **думите от Книгата** · 42 негови изречения, сверени срещу кода | 17 |
| **живото на чисто, старото в архива** · с обяснение вътре | 13 |
| **обещанията** · нищо в кода не твърди за програмата неща, които са бъдеще | 12 |
| **стената** (CSP) · пинат ЦЯЛ низ, не списък от забрани · всеки нов адрес се изброява ПОИМЕННО | — |

## 7 · КАКВО ЗНАЧИ „ЗАТВОРЕН ХОД" · шест условия

Ход (резен, отдел) е затворен само когато **всичките шест** са верни:

| # | условие |
| :--: | :---- |
| 1 | всичките му въпроси имат негов отговор или **ОБЯВЕНО предположение** |
| 2 | `npm run proverka` — деветте порти зелени |
| 3 | `npm run proba` — **два пъти** поред, нула находки |
| 4 | нула нови находки в `chistota`; дублираното не расте над заварените |
| 5 | има ADR, който казва какво беше решено **и какво ОТПАДНА** |
| 6 | **хелпът казва за новото · и на двете степени** |

**Няма „ще го оправим после". Няма половин отдел.**

---

## 8 · ЕДИН ЗАКОН НАД ВСИЧКИ ПРОВЕРКИ

**Червен тест не се изключва и не се маркира като „ще го оправим после".**

И обратното, което е по-важно: **зелен тест над код без викащ ИЗГЛЕЖДА като гаранция и
точно затова е по-опасен от липсващ код.** Затова „построено и невикано" се брои като
ДЪЛГ, не като готовност — този клас дефект е намиран пет пъти за 48 часа и всеки път е
изглеждал като свършена работа.
