## 1 · НОВИЯТ ИНВАРИАНТ · най-важното изречение от 08.09

> **„Не може да се усчетоводяват фактури и Приходи и Разходи от фактури на различни
> фирми. Трябва сигнал и проверка и за таквиа в извлеченита по Банка и вкарание Кеш."**

Това не е екран и не е желание. Това е **инвариант** — нещо, което програмата трябва да
пази винаги, като правило 3 (парите са цели центове) или правило 6 (всеки писач е своя
верига).

**Формулиран за кода:**

> Един ред с пари носи ЕДНА фирма. Сбор, който смесва редове от две фирми, е ГРЕШКА и се
> казва с думи — не се смята мълчаливо.

И втора половина, която е също толкова важна:

> Проверката важи И за банковото извлечение, И за вкарания кеш — тоест на ВХОДА, не само
> на изхода.

**Защо е тежко:** днес нищо в модела не знае какво е фирма. Проверката тече, но
предварителното търсене вече показа, че `grep` за ЕИК, юридическо лице и дружество не
дава нито едно поле в `src/model/`.

## 3 · У2а · ОБЯСНЕН С ПРИМЕР

**Въпросът беше зле зададен. Ето го със случай.**

Ти каза (У2): умението „живее и във файла, и в Книгата". Значи едно и също умение стои на
**две места**. Въпросът е: **какво правим, когато двете се разминат.**

**Случаят:**

> Качваш умение „Анализ на наеми". То влиза и във файл на диска, и в Книгата.
> След три месеца отваряш файла на компютъра — вътре пише едно. Отваряш програмата —
> показва друго. Някой е пипал файла отвън, или Книгата е върната от резервно копие.
> **Кое от двете е истината?**

| тема | **А · Книгата печели** | **Б · файлът печели** | **В · никой не печели · КАЗВА СЕ и ти решаваш** |
| :---- | :---- | :---- | :---- |
| **сигурност** | **+** Книгата минава през Вратата и е подписана · чуждо пипане отвън няма ефект | **−** файл на диска се мени от всеки, който има достъп до папката · подмяна минава тихо | **+** нищо не се приема мълчаливо · **−** иска твоето внимание всеки път |
| | **← печели А** | | |
| **данни** | **+** правило 1: Журналът помни всяка версия | **−** файлът помни само последната | **+** и двете се пазят, разликата се записва |
| | | | **← печели В** |
| **какво губиш** | губиш ръчната поправка във файла — тя се игнорира | губиш подписаната история — файлът я бие | не губиш нищо, но чакаш решение |
| | | | **← печели В** |
| **кога боли** | боли, ако си поправил файла нарочно и програмата го е пренебрегнала | **боли най-много:** чужда подмяна става истина | боли само с време |
| | **← печели А** | | |
| **код в редове** | ~30 | ~30 | ~90 (но **80 от тях вече ги има**) |
| | | | **← печели В** |
| **обратимост** | обратимо | **−** тихо приетата подмяна не се забелязва | обратимо |
| | | | **← печели В** |

**Готовото, което вече съществува:** `src/kniga/sverchik.ts` — **Сверчикът**. Той е
построен точно за този случай: сверява две копия на една истина, казва кое се разминава и
оставя решението на човек. Тоест вариант В **не иска нова машина** — вика съществуваща.

☐ **А** · Книгата винаги печели
☐ **Б** · файлът винаги печели
☑ **В · казва се и ТИ решаваш** ← препоръка · Сверчикът вече го прави за Книгата

## 4 · У1а · ОБЯСНЕН С ПРИМЕР

**Пак със случай.**

Ти каза (У1): има **три** различни неща, и трите се наричат „модел":

| # | кой е | какво пази | пример |
| :--: | :---- | :---- | :---- |
| 1 | **Модел** (поглед) | как ГЛЕДАШ екрана: такт, период, филтър, скрити колони | „Сметки, месечно, само Разходи" |
| 2 | **Модел на Сценарии** | вариант на ДАННИТЕ за период напред · смята се и се сравнява | „ако вдигна наемите с 10 % от януари" |
| 3 | **Бизнес Модел** | шаблон при активиране · кои колони са задължителни, за да тръгне системата | „Строителна фирма" · „Наеми" · „ФЕЦ" |

Днес в кода има **само първото**, и командата се казва `ekran.zapaziModel`.

**Въпросът е:** когато утре запазваш СЦЕНАРИЙ — това същата команда ли е с поле „вид",
или отделна команда с друго име?

| тема | **А · ТРИ отделни думи и три дома** | **Б · ЕДИН механизъм с поле „вид"** |
| :---- | :---- | :---- |
| **яснота** | **+** „Сценарий" значи сценарий · човек чете екрана и разбира | **−** „модел вид 2" не значи нищо за човек |
| | **← печели А** | |
| **сигурност** | **+** право върху сценарии ≠ право върху погледи | **−** едно право отваря и трите |
| | **← печели А** | |
| **данни** | **+** всеки носи СВОИТЕ полета · сценарият има суми, погледът няма | **−** един запис с половината полета празни · правило 29 („полето е типизирано") страда |
| | **← печели А** | |
| **код в редове** | ~3 × 90 = ~270 | ~120 |
| | | **← печели Б** |
| **К1** (осемте прозореца) | и трите живеят в съществуващи прозорци · нов няма | същото |
| | равни | равни |
| **обратимост** | **+** махаш един, другите не мърдат | **−** разделянето после мени всеки стар запис |
| | **← печели А** | |

**Тежкото, което вече е записано** (`docs/18` §3): днешният „модел" е **непрозрачен за
домейна** — `ADR-014:36` казва „Журналът пази карта ключ → стойност; какво значат
ключовете, знае само екранът". Сценарият обаче трябва да се СМЯТА. Значи той **не може**
да ползва днешния механизъм, дори да искаме — той е сляп по конструкция.

☑ **А · три отделни думи и три дома** ← препоръка · защото второто и третото трябва да се смятат, а първото — не
☐ **Б** · един механизъм с поле „вид"

## 4б · КАКВО НАМЕРИ ПРОВЕРКАТА · 13 агента по фирмата

### Доброто · К1 НЕ Е застрашен

**„Таб" при него значи ПОДТАБ, не девети прозорец.** Това е установено четене, не
догадка: `docs/ADR-007:42` и `zadanie/10-dopalneniya-05-09.md:13` („осемте прозореца
остават осем: „таб" при него е и подтаб — както Главни Настройки").

Значи „отделеният за бизнеса таб" и „свой малък Сметки" са **подтабове на Сметки**, и
**К1 остава непокътнат.** Тревогата, която вдигнах по-рано, отпада.

### И една капана, който вече е платен веднъж

**Правило 18 („скритото ПАК се смята") прави невъзможно** „не влиза в основния таб" да се
направи чрез скриване. Точно това вече ни струва находка **Т1** — спряна секция изяждаше
пари от сбора и от изнесената Книга (`docs/14:144`). Значи разделянето по фирма трябва да
е **разделяне на ДАННИТЕ**, не скриване на екрана.

### Номерацията

`src/smetach/nomeratsiya.ts:47` брои **по позиция в таблицата**. Делят ли две фирми
`imoti`, номерата им се преплитат — първата получава 1, 3, 5. А неговата Книга иска
`3.1.1.27` да значи „Студентски Град" завинаги. Това потвърждава отговора му на Ф7.
