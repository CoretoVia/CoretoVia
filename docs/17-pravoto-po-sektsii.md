## 2 · ШЕСТТЕ ВЪПРОСА · с тикчета

### С1 · Тикчето ДВОИЧНО ли е, или носи трите нива?

Правото има три нива (`Редактира · Вижда · Скрито`), а тикчето е две състояния.

| тема | **А · тикче = двоично** (дадена / не) | **Б · три състояния в едно тикче** | **В · ДВЕ колони тикчета** (вижда · пише) |
| :---- | :---- | :---- | :---- |
| **сигурност** | **−** губи „вижда, но не пише" — а точно това е Наблюдателят | **+** пълно · **−** трето състояние се бърка визуално | **+** пълно и явно |
| | | | **← печели В** |
| **данни** | **−** не може да изрази днешните базови редове | **+** изразява всичко · **−** нестандартна контрола | **+** изразява всичко |
| | | | **← печели В** |
| **код в редове** | ~60 | ~110 (своя контрола) | ~90 |
| | **← печели А** | | |
| **обликът** | най-прост · **−** но лъже за модела | **−** тристепенно тикче го няма в никой познат продукт | **+** две ясни колони, като таблица (правило 28) |
| | | | **← печели В** |
| **обратимост** | **−** после добавянето на второ ниво мени Книгата | обратимо | обратимо |
| | | | **← печели В** |

**Кой го ползва · проверено:** двете колони „четене · писане" са начинът, по който
**Google Drive** (Viewer · Editor), **GitHub** (Read · Write) и файловите права на
**Unix** (r · w) разделят виждането от писането. Тристепенно тикче няма масов образец.

☐ **А** · тикче = двоично · просто, но губи „вижда без да пише"
☐ **Б** · три състояния в едно тикче
☑ **В · ДВЕ колони тикчета: „вижда" и „пише"** ← препоръка

### С2 · Приход и Разход — по СТРАНА или по всяка отделна секция?

Те са две отделни номенклатури, значи и двете са възможни.

| тема | **А · по СТРАНА** (Приход / Разход, две тикчета) | **Б · по всяка СЕКЦИЯ** (Заплати, Наеми, Ток…) | **В · и двете · страна дава всичко, тикче маха отделни** |
| :---- | :---- | :---- | :---- |
| **сигурност** | **−** грубо: „Разход" отваря и Заплатите | **+** най-фино · **−** лесно се пропуска секция | **+** фино и с бърз ход |
| | | | **← печели В** |
| **удобство** | **+** два клика | **−** двайсет клика | **+** един клик за всичко, после уточняване |
| | | | **← печели В** |
| **код в редове** | ~40 | ~70 | ~100 |
| | **← печели А** | | |
| **обещание** | **−** „дай му Разходите без Заплатите" е невъзможно, а точно това иска бизнесът | **+** възможно | **+** възможно |
| | | | **← печели В** |

**Защо това не е измислен проблем:** негово от 05.09 — Помощник Управителят получава
точно ТРИ неща (Заплати · Фактури Кеш · Фактури Карта), не цялата страна Разход
(`zadanie/11` §3). Значи „по страна" сама по себе си не стига.

☐ **А** · само по страна (Приход · Разход)
☐ **Б** · само по отделна секция
☑ **В · и двете · страната дава всичко наведнъж, после се махат отделни** ← препоръка

### С3 · НОВА секция, създадена след раздаването — кой я вижда?

Секциите растат — създават се от Настройки. Утре има нова секция „Ремонти". Кой я вижда?

| тема | **А · НИКОЙ без изрично тикче** (затворена) | **Б · всеки, който има „всичко"** (отворена) | **В · този, който я е създал** |
| :---- | :---- | :---- | :---- |
| **сигурност** | **+** нищо не изтича само · **−** нов разход не се вижда, докато не се раздаде | **−** нова секция изтича към всички наведнъж | **−** зависи кой е натиснал бутона |
| | **← печели А** | | |
| **удобство** | **−** всяка нова секция иска обиколка на Длъжностите | **+** нула работа | **−** непредвидимо |
| | | **← печели Б** | |
| **обещание** | „каквото не съм дал, не се вижда" | „дал съм всичко значи и бъдещото" | няма ясно обещание |
| | **← печели А** | | |
| **обратимост** | изтекло не се връща · **А го предотвратява** | **−** изтеклото се е видяло вече | — |
| | **← печели А** | | |

**Кой го ползва · проверено:** **затворено по подразбиране** (default deny) е основното
правило на всяка система за достъп — AWS IAM, Kubernetes RBAC и Unix всички отказват,
докато не се даде изрично.

**Но има уловка:** ако „Редактира всичко" значи буквално „всичко", то новата секция
влиза автоматично. Тогава А важи само за онзи, който има СПИСЪК, не „всичко".

☑ **А · затворена · никой без тикче** (но „всичко" си остава всичко) ← препоръка
☐ **Б** · отворена за всеки с „всичко"
☐ **В** · само създателят

### С4 · Къде ЖИВЕЕ правото — в изречението, или в ново поле?

Днес всяка ос е НЕГОВО ИЗРЕЧЕНИЕ в клетка на лист Служители. К1 казва: Книгата е Заданието.

| тема | **А · остава изречение** („Редактира секции: Приход, Заплати") | **Б · ново поле със списък** | **В · изречението е домът, тикчетата го ПИШАТ** |
| :---- | :---- | :---- | :---- |
| **данни** | **+** листът не се мени изобщо | **−** мени листа Служители = мени ДАННИ (като О5) | **+** листът не се мени |
| | | | **← равни А и В** |
| **сигурност** | **−** свободен текст се пише с грешка и правото тихо се разширява | **+** списък не може да се сбърка | **+** тикчето не може да сбърка правописа |
| | | | **← печели В** |
| **код в редове** | ~50 (парсерът вече го има) | ~120 + миграция | ~90 |
| | **← печели А** | | |
| **обещание** | **+** думите му остават негови · чете се от човек в Ексел | **−** списък в клетка не се чете така лесно | **+** думите остават негови И се пишат машинно |
| | | | **← печели В** |
| **обратимост** | обратимо | **−** стар файл спира да се чете | обратимо |
| | | | **← печели В** |

**Ключовото:** вариант В **не пипа нито една клетка от формата** — тикчетата само
съставят същото изречение, което човек би написал на ръка. Тоест Книгата му остава
четима в Ексел, а грешният правопис изчезва.

☐ **А** · остава свободно изречение (както днес)
☐ **Б** · ново поле със списък
☑ **В · изречението остава домът, но тикчетата го пишат вместо ръката** ← препоръка

### С5 · ОБЛИКЪТ · коя контрола

Негово: „с тикчета най добре или падащи менюта… Най удобния и функционален да е дизайна."
Тоест изборът е делегиран — тук е сравнението, за да е видим.

| тема | **А · списък с тикчета, всичко наведнъж** | **Б · падащо меню с тикчета вътре** | **В · таблица: редове = секции, колони = вижда · пише** |
| :---- | :---- | :---- | :---- |
| **удобство** | **+** всичко се вижда · **−** при 30 секции става дълго | **+** компактно · **−** два клика до всяко | **+** вижда се всичко наведнъж и в двете оси |
| | | | **← печели В** |
| **правило 28** (всичко е Ексел) | списък не е таблица | меню не е таблица | **+ ТАБЛИЦА е** |
| | | | **← печели В** |
| **правило 29** (равни и типизирани) | **+** | **+** | **+** и е същата решетка като останалия продукт |
| | | | **← печели В** |
| **код в редове** | ~70 | ~90 | ~60 (решетката вече съществува) |
| | | | **← печели В** |

**Защо В печели и по цена:** решетката вече е построена и рисува таблици. Правото по
секции Е таблица — секции по вертикала, две права по хоризонтала. Нищо ново не се
изобретява.

☐ **А** · списък с тикчета
☐ **Б** · падащо меню с тикчета
☑ **В · ТАБЛИЦА · секции по редове, „вижда" и „пише" като колони с тикчета** ← препоръка

### С6 · Правото и ЛИЧНИЯТ ИЗГЛЕД — един списък или два?

`zadanie/01:19` вече дава Личен Изглед: човек си скрива колони. Ако сега се дават и секции,
двете лесно се бъркат — а те са РАЗНИ неща:

| | **правото** | **личният изглед** |
| :---- | :---- | :---- |
| кой решава | Длъжността (Стопанинът) | самият човек |
| за какво служи | сигурност | удобство |
| може ли да разшири | **не** — правило 18: правото само СТЕСНЯВА | не, само стеснява още |

| тема | **А · два отделни списъка** | **Б · един списък, две употреби** |
| :---- | :---- | :---- |
| **сигурност** | **+** човек не може да си пипне правото · **−** две места за поддръжка | **−** един бъг ги слива и човек си отваря секция |
| | **← печели А** | |
| **обликът** | **+** еднаква контрола, различен екран (правило 29) | **+** едно място |
| | **← печели А** | |
| **код** | ~40 повече | по-малко |
| | | **← печели Б** |

☑ **А · два отделни списъка · еднакви на вид, различни по власт** ← препоръка
